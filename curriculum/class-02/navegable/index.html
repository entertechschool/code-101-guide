Bajar al piso 1

Flujo de renderizado

Concepto

¿Qué es renderizar? Convertir el código de tu página en lo que ves en pantalla.

Lo hace el navegador cada vez que abres o recargas una página. El término viene del inglés to render, "producir" o "representar". El archivo sigue siendo texto: el navegador lo interpreta y dibuja el resultado.

El flujo tiene tres pasos:

  1. Lee el HTML de arriba hacia abajo, línea por línea.
  2. Crea un elemento por cada etiqueta que encuentra.
  3. Dibuja esos elementos en el mismo orden. Si todavía no hay CSS, usa sus estilos por defecto: por eso un <h1> sale grande sin que se lo pidas.

Figura

Ojo

Al llegar a <img src="img/perfil.jpg">, el navegador va a buscar el archivo por esa ruta. Si está mal, dibuja el ícono roto y el alt, y sigue con lo demás.

Bajar al piso 2

El diseño antes de codear

Apertura

¿Construirías una casa sin plano? Los obreros levantan paredes según lo que cada uno recuerda y, al terminar, el baño queda sin ventana y la escalera choca con el techo. Arreglarlo significa tumbar lo que ya se hizo. Por eso una casa se dibuja antes de construirse, y una página web también.

Figura: la casa sin plano y la casa con plano

Qué pasa si codeas sin diseñar

  • Decides mientras escribes, y cambias de idea cuando ya hay código hecho.
  • Rehaces trabajo: mover una sección obliga a reordenar lo que dependía de ella.
  • Olvidas partes y las notas recién al ver la página terminada.
  • Nadie puede opinar hasta que la página existe, cuando cambiarla ya cuesta más.

Concepto

¿Qué son los niveles de diseño? Etapas de un diseño, según cuánto se parece al producto final.

Esa cercanía se llama fidelidad, y cada nivel la sube: primero se decide dónde va cada cosa, luego cómo se ve y al final cómo responde.

Wireframe
El plano. Cajas y líneas que muestran qué va en cada lugar.
Mockup
La imagen de cómo se verá, con colores, fuentes y fotos. No se puede usar.
Prototipo
Una simulación en la que puedes hacer clic y pasar de una pantalla a otra.

Figura: los tres niveles de diseño

Colores y fotosNoSíSí

Ninguno de los tres es código que el navegador renderice. Empieza por el wireframe.

Bajar al piso 3

Wireframe

Concepto

¿Qué es un wireframe? Un dibujo simple que muestra la estructura de una página.

La palabra viene del inglés wire y frame, "armazón de alambre". Lleva rectángulos para los bloques, una equis para las imágenes, líneas para el texto y el nombre de cada parte. Deja fuera el color y el diseño final, porque ahí solo se decide qué contenido hay y dónde va.

¿Cuándo hacer un wireframe?

Sí

  • Antes de escribir el HTML de una página nueva.
  • Cuando la página tiene varias secciones y hay que decidir su orden.
  • Cuando quieres que alguien opine antes de que escribas código.

No

  • Para corregir un texto o un detalle en una página que ya existe.
  • Para decidir colores y fuentes: eso va en el mockup.

Con qué hacer un wireframe

  • Papel y lápiz: lo más rápido para una primera idea.
  • Excalidraw: gratis, funciona en el navegador y no pide cuenta. Tiene aspecto de dibujo a mano.
  • Balsamiq: pensado solo para wireframes, con piezas listas. Es de pago, con prueba gratis.
  • Figma: sirve para los tres niveles de diseño. Tiene plan gratis y pide cuenta.

Figura

Error común

Empiezas a elegir colores y fuentes en el wireframe.

Pasa porque se confunde con el mockup, y la conversación se va al aspecto cuando la estructura todavía no está resuelta.

Para detectarlo, mira tu dibujo: si tiene colores elegidos, fotos reales o una fuente escogida, ya saliste del wireframe. Vuelve a las cajas.

Bajar al piso 4

Etiqueta div

Concepto

¿Qué es una etiqueta contenedora? Una etiqueta que envuelve a otras para agruparlas.

Ya usaste algunas: <body> contiene toda la página visible y <ul> contiene sus <li>. Cada una tiene un propósito específico.

<div> es la contenedora genérica. Su nombre viene de division, "división", y agrupa cualquier cosa sin decir qué es. Por defecto ocupa todo el ancho disponible y empieza en una línea nueva.

Figura

¿Cuándo usar un div?

Sí

  • Para agrupar elementos y luego darles un estilo juntos con CSS.
  • Para armar bloques de tu diseño, como una tarjeta o una columna.

No

  • Cuando existe una etiqueta que dice qué es ese contenido, como las que vienen en los apuntes siguientes.
  • Para envolver un solo elemento sin ninguna razón.

Ejemplo

<!-- Una tarjeta: la foto, el nombre y el precio forman un solo bloque -->
<div>
  <img src="img/taza.jpg" alt="Taza blanca">
  <h3>Taza blanca</h3>
  <p>S/ 25</p>
</div>

Ojo

Sin CSS, un <div> no se ve: no trae borde, fondo ni color. Solo notarás que su contenido empieza en una línea nueva.

Bajar al piso 5

HTML semántico

Apertura

Te mudas y tienes dos opciones: 50 cajas iguales sin nada escrito, o cajas con "Cocina", "Baño" y "Dormitorio". ¿Cuáles prefieres? En las dos está todo, pero en la primera tienes que abrir caja por caja para saber qué hay. Con una página hecha solo de <div> pasa igual.

Figura: las cajas de mudanza

El problema de usar muchos div

Como <div> no dice qué contiene, una página armada solo con él obliga a leer cada bloque para saber qué parte es. Los cierres se vuelven una fila de </div> iguales, y un lector de pantalla tampoco puede avisar dónde está el menú o dónde empieza el contenido principal.

Concepto

¿Qué es el HTML semántico? Usar etiquetas cuyo nombre dice qué contenido llevan.

Semántica viene del griego y se refiere al significado. <div> solo marca un bloque; <footer> marca el pie de la página. Un lector de pantalla es un programa que lee la página en voz alta a quien no puede verla, y usa esas etiquetas para orientar a la persona.

Figura: el mismo código con div y con etiquetas semánticas

Diferencias entre usar solo div y usar etiquetas semánticas

CriterioCon solo divCon etiquetas semánticas
Leer tu códigoHay que revisar cada bloque para saber qué esEl nombre de la etiqueta lo dice
Encontrar un cierreTodos son </div></nav> y </main> se distinguen
Lector de pantallaNo puede avisar qué parte es cada unaAnuncia las partes y permite saltar entre ellas
BuscadoresTienen que deducir qué parte es la principalLa etiqueta les indica qué parte es cada una

Usa la etiqueta semántica cuando exista una para ese contenido, y deja <div> para agrupar lo demás.

Error común

Eliges la etiqueta por el lugar o el aspecto que quieres. Aquí, el aviso va en <header> solo porque debe quedar arriba:

<!-- Mal: esto es parte del contenido, no el encabezado de la página -->
<header>
  <p>Hoy cerramos a las 6 p. m.</p>
</header>

Pasa porque se cree que la etiqueta decide cómo se ve. Una etiqueta semántica se ve igual que un <div>: la posición y el aspecto los da el CSS.

Para detectarlo, pregúntate qué es ese contenido, sin pensar en dónde lo quieres. Si la respuesta no coincide con el nombre de la etiqueta, cámbiala.

Bajar al piso 6

Etiquetas semánticas

Concepto

¿Cuáles son las etiquetas semánticas principales? Cinco que dividen una página en sus partes.

Todas van dentro de <body>, necesitan cierre y por defecto se comportan como un <div>.

La etiqueta <header>
El encabezado de la página, del inglés head, "cabeza". Lleva lo que la presenta: el nombre, el logo, a veces el menú. 
<header>
  <h1>Recetas de la abuela</h1>
</header>
La etiqueta <nav>
El grupo de enlaces principales para moverse por el sitio. Viene de navigation. Puede ir dentro de <header>. 
<nav>
  <!-- Aquí van los enlaces del menú -->
</nav>
La etiqueta <main>
El contenido principal, del inglés main, "principal". Es aquello por lo que alguien entró a tu página. 
<main>
  <!-- Las secciones de la página -->
</main>
La etiqueta <section>
Un bloque de contenido sobre un mismo tema. Normalmente empieza con su propio título. 
<section>
  <h2>Postres</h2>
  <p>Mis recetas dulces favoritas.</p>
</section>
La etiqueta <footer>
El pie de la página, del inglés foot, "pie". Lleva lo que va al cierre: contacto, redes, derechos de autor. 
<footer>
  <p>Contacto: 999 999 999</p>
</footer>

Figura

Ojo

<main> va una sola vez por página. <section> se repite cuantas veces haga falta, una por cada tema.

Bajar al piso 7

Atributo id

Apertura

En Perú hay muchas personas llamadas Ana Torres, pero cada una tiene su propio número de DNI, y con él se identifica a una sola. En una página pueden repetirse muchos <section>, y para señalar exactamente uno existe id.

Concepto

¿Qué es id? Un atributo que le da a un elemento un nombre único dentro de la página.

Viene de identifier, "identificador". No cambia cómo se ve el elemento, solo permite encontrarlo. Se puede usar en casi todas las etiquetas HTML, no solo en <section>.

Figura

Cómo escribir un id

  1. Escríbelo dentro de la etiqueta de apertura: <section id="postres">.
  2. Usa un valor que no se repita en esa página.
  3. Escríbelo sin espacios. Si son dos palabras, únelas con un guion: id="mis-recetas".
  4. Respeta mayúsculas y minúsculas: Postres y postres son valores distintos.
  5. Elige un nombre que diga qué es esa parte: contacto antes que seccion3.

¿Cuándo usar un id?

Sí

  • Para llevar al usuario a una parte de la página con un enlace.
  • Para que CSS o JavaScript encuentren un elemento específico.

No

  • Para ponerle el mismo nombre a varios elementos.
  • En cada etiqueta por costumbre: úsalo solo si algo necesita encontrar ese elemento.

Error común

Repites un id o le pones espacios:

<!-- Mal: "contacto" se repite y "mis recetas" tiene un espacio -->
<section id="contacto">…</section>
<p id="contacto">…</p>
<section id="mis recetas">…</section>

Pasa porque se usa id como un rótulo que se puede repetir. Si dos elementos comparten valor, un enlace a ese id te lleva solo al primero.

Para detectarlo, busca el valor en VS Code con Ctrl + F: debe aparecer una sola vez como id. Y revisa que no tenga espacios.

Bajar al piso 8

Navegación en la web

Concepto

¿Qué es navegar en la web? Pasar a otro lugar haciendo clic en un enlace.

<a> es la etiqueta que crea un enlace. Su nombre viene de anchor, "ancla". El atributo href, de hypertext reference, indica a dónde lleva. Por defecto, el texto del enlace se ve azul y subrayado, y sin href el clic no lleva a ningún lado.

Figura: anatomía de un enlace

Navegación externa

¿Qué es la navegación externa? Ir a otro sitio web.

En href va la URL completa del sitio, empezando con https://.

Figura: navegación externa

Ejemplo

<!-- Lleva a otro sitio: la URL está completa -->
<a href="https://www.google.com.pe">Ir a Google</a>

Ojo

Sin https://, el navegador toma www.google.com.pe como una ruta relativa y busca ese archivo dentro de tu carpeta.

Navegación interna

¿Qué es la navegación interna? Saltar a otra parte de la misma página.

En href va el id del destino, con # adelante.

Figura interactiva: navegación interna

Cómo crear un enlace a otra parte de la página

  1. Ponle un id a la parte de destino: 
    <section id="postres">
  <h2>Postres</h2>
</section>
  2. Crea el enlace, con el mismo valor y # adelante: 
    <a href="#postres">Ver postres</a>
  3. Si tienes varios enlaces, agrúpalos en el menú: 
    <nav>
  <a href="#postres">Postres</a>
  <a href="#contacto">Contacto</a>
</nav>
  4. Abre la página y haz clic: debe saltar a esa sección. Con poco contenido quizá no notes el salto, porque toda la página ya entra en pantalla.

Error común

Olvidas el #:

<!-- Mal: busca un archivo llamado "postres", no una sección -->
<a href="postres">Ver postres</a>

Pasa porque el id se escribe sin # y se copia igual en el enlace. Sin #, el navegador lo trata como una ruta.

Lo detectas al hacer clic: en vez de saltar a la sección, aparece un error de página o archivo no encontrado.

Bajar al piso 9

Conclusiones

Conclusión 1

Una página se planifica antes de escribirla. El wireframe decide qué va en cada lugar, y el mockup y el prototipo agregan detalle encima. El navegador renderiza el código en orden, así que ese plano termina siendo el orden de tu HTML.

Viene de: Flujo de renderizado · El diseño antes de codear · Wireframe

Conclusión 2

Las etiquetas agrupan y también dicen qué es cada parte. <div> agrupa sin decir nada, las etiquetas semánticas nombran el contenido e id señala un solo elemento.

Viene de: Etiqueta div · HTML semántico · Etiquetas semánticas · Atributo id

Conclusión 3

<a> conecta lugares según su href. Con una URL completa vas a otro sitio; con # y un id saltas dentro de la misma página.

Viene de: Atributo id · Navegación en la web
